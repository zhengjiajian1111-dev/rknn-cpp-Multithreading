## 1. 面试怎么考、面试前要做什么

**面试结构**（经验比例）：
- **项目深挖**：约一半时间。从简历上最亮的点往下问，一直问到你答不上来。
- **基础知识**：约三成。多线程、网络、内存、信号、C++，经常用项目里的例子追问。
- **手撕代码**：约两成。生产者消费者、线程池最常见。

**面试前必须做的事**：
- [ ] **上板实测**：拿到每路帧率、NPU 占用、CPU 占用、延迟、内存这几个数字（见第 8 节）。**没有自己测的数字，一问就露馅。**
- [ ] **每个设计都能说出"为什么"**：面试官会随便挑一处问你为什么这么写。
- [ ] **跑一次 ASan 并截图**：证明你查过内存泄漏。
- [ ] **（建议）国标用真实平台对接一次**：用 WVP-PRO + ZLMediaKit，截图。目前只和模拟平台联调过。
- [ ] **融合效果**：没有测过精度提升，就如实说"重点是工程框架"，**不要编数字**。

## 2. 项目介绍怎么说

> 所有数字必须是你自己测的，`【实测】` 处换成第 8 节测到的数据。

**30 秒版**：
> 我做过一个 RK3588 上的多路视频智能分析项目：同时接入 4 路视频，用 MPP 硬件解码、RGA 做图像处理、NPU 做目标检测，支持多模型结果融合，结果拼成一个画面显示，同时支持 RTMP、RTSP、GB28181 推流。我主要负责多线程架构、推理调度和推流部分。

**1 分钟版**：
> 项目跑在 RK3588 上，做 4 路视频的实时目标检测。每一路是一条独立的流水线：FFmpeg 拉流，MPP 硬件解码，RGA 转成 BGR，送到 NPU 推理。NPU 有三个核，我建了多个模型实例，轮流绑到三个核上，多路同时推理。检测结果融合、画框后拼成一个画面，本地显示，同时编码推流。
>
> 工程上主要解决了三个问题：
> 一是多线程解耦：拉流、解码、推理分开，压缩数据用有界队列、图像只保留最新帧，下游慢的时候延迟不会越积越多；
> 二是实时性：目标帧率控制、跳帧推理，每一级都有明确的丢帧策略；
> 三是稳定性：断流自动重连、推流断线重连、线程安全退出，用 ASan 查过内存泄漏。
>
> 在板子上 4 路 1080p 每路 `【实测】` fps，NPU 占用 `【实测】`，延迟约 `【实测】` 毫秒。

**被问"你负责哪部分"**：如实说。答不上来的地方，比硬撑更好的说法是："这块我参考了官方示例的用法，原理我理解的是……，细节回去再确认。"

## 3. 项目高频问题

### A. 架构与多线程（问得最多）

**A1 整体架构讲一下？**
每路一条流水线：拉流 → 解码 → 转换 → 推理 → 融合；各路结果交给拼接线程，拼成一个画面，显示并推流。每路 3 个线程（拉流、解码、推理），另外有拼接线程、推流线程、主线程，多模型时还有一个推理线程池。

**A2 线程之间怎么通信？**
两种缓冲区：
- **拉流 → 解码**用有界队列：压缩数据不能随便丢；
- **解码之后**用"最新帧缓冲"：只保留最新一帧，新帧覆盖旧帧。

两种都是"互斥锁 + 条件变量"实现。

**A3 下游处理不过来怎么办？**
每一级都有丢帧策略：
- 拉流时，实时流队列满了，丢掉积压的整组画面，等下一个关键帧；
- 解码后，推理没来得及取，新帧覆盖旧帧；
- 推理前，超过目标帧率的帧直接丢；
- 推理时，可以设置每 N 帧推理一次，中间帧复用上次的结果。

丢了多少都会计数，看哪一级开始丢帧，就知道瓶颈在它的下游。

**A4 多路抢 NPU，资源竞争怎么处理？会不会死锁？**
- **竞争**：4 个推理线程共用 3 个模型实例。
- **实例池**：用一个"实例池"管理，借用时加锁，没有空闲的就在条件变量上等，用完归还并叫醒等待的线程，保证一个实例同一时刻只被一个线程使用。
- **不死锁**：线程池线程数 = 实例数，每个任务只借一个实例，借到后一定能算完归还，不会"拿着一个再等另一个"，破坏了死锁的"占有并等待"条件。

**A5 线程池在项目里怎么用的？**
只在多模型时用。同一帧要跑 A、B 两个模型，推理线程把两个任务提交到线程池，拿到两个 `future`，两个模型在不同 NPU 核上同时算，都完成后再融合。一帧只花一个模型的时间，而不是两个相加。单模型时不走线程池，推理线程直接算。

**A6 程序怎么安全退出？`std::thread` 析构会怎样？**
- `std::thread` 析构时如果还没 join，会直接 `std::terminate`；线程里有没捕获的异常也会 terminate。我用 `WorkerThread` 封装：析构时 join，线程入口统一捕获异常。
- 退出分三步：
  1. 通知所有线程停止，并关闭所有缓冲区，把等待中的线程都叫醒；
  2. 按拉流 → 解码 → 推理 → 输出的顺序等线程结束；
  3. 最后释放 NPU 资源。
- 信号处理函数里只设置一个原子标志；另外要忽略 SIGPIPE。

**A7 为什么先加载模型、最后启动拉流？**
- 模型加载最容易失败，放在最前面，失败时还没有线程和网络连接，退出很干净；
- 消费者先启动、生产者最后启动，第一帧到来时下游都已准备好。

**A8 图像在多个线程之间传递怎么保证安全？**
约定"发布后不再修改"：解码线程每帧新建一个图像写入缓冲区，之后不再改它；只读的线程直接用；要修改的线程（推流时叠加时间）先拷贝一份再改。

### B. 音视频基础

**B1 I 帧、P 帧、B 帧、GOP、SPS/PPS？**
- I 帧：自己就能解码；
- P 帧：参考前面的帧；
- B 帧：参考前后的帧，压缩率高，但延迟大，所以实时推流不用；
- GOP：两个 I 帧之间的一组画面；
- SPS/PPS：分辨率等解码参数，解码器必须先拿到它们。

**B2 为什么丢包要丢到下一个关键帧？**
P 帧依赖前面的帧，中间丢一个，后面整组都会花屏，直到下一个 I 帧。所以要么不丢，要丢就丢一整组。

**B3 NV12 格式和 stride？**
- NV12：先存亮度 Y，再存交错的颜色 UV，每 4 个像素共用一组颜色，大小是宽 × 高 × 1.5。
- stride：硬件要求内存对齐，一行实际占的字节数可能比宽度大，高度也会对齐（1080 → 1088）。**颜色数据的起点是 stride × 对齐后的高度**，按宽 × 高算，画面会发绿。

**B4 什么是零拷贝？**
MPP 解码出的图像在硬件内存里，有一个文件描述符（fd）。把 fd 直接交给 RGA，RGA 直接读这块内存，CPU 不搬数据。

**B5 MPP 解码流程？**
创建解码器 → 送入压缩数据 → 取出解码图像 → 用完马上归还缓冲区。第一帧会先通知需要多大缓冲区，按这个大小分配一组，并且限制数量，防止下游卡住时内存无限增长。

### C. 推理与融合

**C1 NPU 三个核怎么用起来的？**
- 第一个实例加载模型，其余实例用 `rknn_dup_context` **共享权重**；
- 用 `rknn_set_core_mask` 把实例轮流绑到三个核上；
- 多路推理线程各借一个实例，就能同时在三个核上跑。

**C2 预处理和后处理做了什么？**
- 预处理：等比缩放到 640×640，多出来的地方补灰边（letterbox）。
- 后处理：从 YOLOv5 输出里算出框和分数，分数 = 有目标的概率 × 类别概率，过滤低分框，再做 NMS。
- 框要换算回原图：`x原图 = (x模型 − 灰边) / 缩放比例`。

**C3 NMS 原理？你修的 bug 是什么？**
- **原理**：按分数排序，每次保留最高分的框，删掉和它重叠度（IoU）超过阈值的**同类**框。
- **bug**：原代码排序后的下标和原始下标混用，还没检查类别，会出现"车框把人框删了"；我改成统一用原始下标，并按类别判断。
- **另一个问题**：标签原来是全局数组，多线程同时初始化会竞争，我改成每个模型自己持有。

**C4 为什么要多模型融合？怎么融合？**
- **为什么**：单个模型会漏检和误检。多个模型可以互补（通用模型找人，专用模型找安全帽），可以互相核对减少误报，也可以互相兜底减少漏报。
- **怎么做**：
  1. 所有框按分数排序；
  2. 同类、重叠度高的框认为是同一个目标，分到一组，每个模型在一组里最多一个框；
  3. 每组合成一个框（按分数加权平均）；
  4. 投票：`min_votes=1` 取并集，漏报少；`min_votes=模型数` 取交集，误报少；
  5. 最后再做一次 NMS。
- **代价**：NPU 工作量翻倍。
- **注意**：代码支持多模型，默认只配了一个模型。

**C5 跳帧推理有什么副作用？**
中间帧用的是旧的框，目标运动快时框会滞后。所以复用结果有时效，超过 0.5 秒就不画。更好的办法是中间帧用跟踪算法预测框的位置。

### D. 推流与 GB28181

**D1 RTMP 和 RTSP 的区别？**
- RTMP 基于 TCP，用 FLV 封装，常推给直播服务器，延迟 1~3 秒；
- RTSP 常用于监控摄像头，视频走 RTP，可以选 TCP 或 UDP，延迟更低。
- UDP 快，但可能丢包；TCP 可靠，但网络差时卡顿明显。

**D2 为什么要等关键帧再建立推流连接？**
对方收到的第一帧必须是关键帧才能解码，否则会黑屏或花屏。关键帧前还要带 SPS/PPS，中途接入的观众才能看。

**D3 SIGPIPE 是什么？**
往已经断开的 TCP 连接写数据，内核会发 SIGPIPE，默认直接杀死进程，而且没有任何日志。推流服务器一重启，程序就"无声无息地退出"。解决：忽略 SIGPIPE，让写操作返回错误，由程序自己重连。

**D4 断线怎么重连？为什么等待时间要翻倍？**
- 先关闭旧连接，再等一会儿重连，等待时间逐次翻倍（拉流从 0.5 秒开始，推流从 1 秒开始），有上限；连上后重置。
- 翻倍的原因：服务器长时间不可用时，避免疯狂重试；很多设备同时断线时，也不会在服务器恢复瞬间一起涌上去。
- 先关旧连接的原因：避免服务器上残留旧会话，导致新连接被当成重复推流而拒绝。

**D5 GB28181 是什么？流程是什么？**
- **是什么**：国内视频监控联网的国家标准，公安、政府类项目要求设备都能接入国标平台。和 RTMP/RTSP 的区别是：设备先去平台注册，**等平台点播才发视频**。
- **两部分**：信令用 SIP 协议（注册、心跳、点播、挂断）；媒体是 H.264 打包成 PS 格式，再用 RTP 通过 UDP 或 TCP 发送。
- **流程**（最好能画出来）：
  - 注册 → 平台要求认证 → 带认证（MD5 摘要）再注册 → 成功；
  - 定时发心跳；
  - 平台点播（带接收地址和流编号 SSRC）→ 设备同意 → 平台确认 → 设备开始发视频；
  - 平台挂断 → 停止。

**D6 国标里有哪些要注意的点？**
- **SSRC** 必须用平台点播时给的值，平台靠它认出是哪一路流。
- **心跳**连续几次没回应，就认为平台掉线，重新注册。
- **重复点播**：平台重发同一个请求时原样回复，不开第二路视频；推流中来了新点播，替换旧的或拒绝新的（可配置）。
- **端口**被占用就换一个。
- **没人点播时不编码**，节省资源。

**国标要掌握到什么程度**：
- 投普通 Linux 应用岗：会 D5、D6 就够了，能画出注册和点播流程。
- 岗位写了安防或国标：再了解 MD5 摘要认证大致怎么算、PS 包的大致结构（关键帧前带流类型声明）、TCP 模式下谁主动连接。
- 不用背协议细节。

### E. 调试

**E1 内存泄漏怎么查？**
1. 先确认是不是真泄漏：观察内存曲线，涨到一定程度就平了的，不是泄漏；一直线性上涨才是。
2. 分类：打开的连接数在涨，是没关连接；线程数在涨，是线程没回收；硬件内存在涨，是 MPP/NPU 缓冲区没释放；普通内存在涨，用 ASan 找分配位置。
3. 硬件内存 ASan 查不到，要看系统的 CMA 用量，并检查每个"申请"都有对应的"释放"。
4. 缩小范围：逐个关掉模块，看关掉哪个之后泄漏消失。

**E2 程序卡死怎么查？**
`gdb -p 进程号`，`thread apply all bt` 看每个线程卡在哪：等锁、等条件变量，还是等网络。退出时卡死，最常见的原因是有缓冲区没关闭，线程还在等。

**E3 程序崩溃怎么查？**
打开 core dump，用 gdb 看崩溃时的调用栈；越界、重复释放用 ASan 复现。进程没有任何日志就消失了，先怀疑 SIGPIPE 和系统内存不足被杀（OOM）。

**E4 性能瓶颈怎么定位？**
看程序自带的性能报告（每个阶段的次数、耗时、负载）和丢帧计数；`top -H` 看每个线程的 CPU；看 NPU 三个核的占用。先用 `performance.sh` 定频，减少测试误差。

### F. 扩展

**F1 如果要支持 16 路、32 路？**
- NPU 会先成为瓶颈：降低推理帧率、跳帧、用更小的模型；
- 线程模型改成少量工作线程加事件驱动，而不是每路 3 个线程；
- 减少内存拷贝，复用图像缓冲区。

**F2 延迟怎么测？**
摄像头对着一个毫秒计时器，把计时器和显示画面拍在同一张照片里，两个时间相减。多拍几次取平均。

## 4. 基础知识（和项目挂钩）

**条件变量为什么要用 while（或带条件的 wait）？**
线程可能在没人通知时醒来（虚假唤醒），也可能醒来时条件已被别的线程改掉，所以醒来后要重新检查。项目里所有等待都是带条件、带超时的写法。

**notify_one 和 notify_all？**
多了一个数据，叫醒一个就够（notify_one）；关闭、停止这种全局变化，必须全叫醒（notify_all），否则有线程永远醒不来。

**死锁的四个条件？怎么避免？**
四个条件：互斥、占有并等待、不可剥夺、循环等待。
避免方法：固定加锁顺序、一次只持有一个资源、加锁带超时。项目里线程池线程数等于实例数，每个任务只借一个实例，就是破坏"占有并等待"。

**atomic 和 volatile？**
`volatile` 只保证不被编译器优化，不保证原子性，不能用来做线程同步；`atomic` 保证操作是原子的。项目里停止标志、统计计数都用 `atomic`。

**线程池原理？线程数怎么定？**
提前建好线程，从任务队列取任务执行，避免反复创建线程。
- 计算密集型：线程数 ≈ CPU 核数；
- IO 密集型：可以多一些；
- 受外部资源限制时，按资源数定（项目里 = 模型实例数）。

**进程和线程的区别？进程间通信有哪些？**
- 进程是资源分配单位，有独立的内存空间；线程是调度单位，共享进程的内存。
- 进程间通信：管道、消息队列、共享内存（最快）、信号量、信号、socket。
- 项目用多线程，因为各级之间要传大图像，共享内存最方便。

**select、poll、epoll 的区别？**
- select 最多 1024 个连接，每次都要把全部连接拷贝进内核、遍历检查；
- poll 没有数量限制，但也要遍历；
- epoll 只注册一次，内核直接返回有数据的连接，连接多时效率最高。

项目里国标信令只有一个连接，用 poll 足够。

**TCP 和 UDP？音视频为什么常用 UDP？**
TCP 可靠、有序，但丢包重传会卡住后面的数据；UDP 不可靠，但延迟低。实时视频"宁可丢一帧也不要卡住"，所以常用 UDP；网络差或要穿透防火墙时用 TCP。

**TCP 粘包？**
TCP 是字节流，没有消息边界，要自己分：定长、分隔符、或者在前面加长度（最常用）。项目里国标 TCP 传输就是每个包前加 2 字节长度。

**信号处理函数里能做什么？**
只能做很简单的事（比如设置一个标志），不能调用 `printf`、`malloc`、加锁，因为信号可能在主流程持有锁时到来，导致死锁。项目里退出信号只设置一个原子标志。

**malloc 原理？RSS 是什么？**
- 小块内存从堆上分配，释放后放回空闲链表复用，不一定马上还给系统；大块内存直接向系统申请，释放时立即归还。
- RSS 是进程实际占用的物理内存，查泄漏主要看它的趋势（`/proc/进程号/status`）。

**智能指针？shared_ptr 线程安全吗？**
- unique_ptr：独占；shared_ptr：共享，靠引用计数；weak_ptr：不增加计数，用来打破循环引用。
- shared_ptr 的引用计数是原子的，多个线程各自拷贝没问题，但它指向的对象本身没有保护。

**RAII？**
构造时获取资源，析构时释放，出了作用域自动释放，出错也不会漏。项目里线程封装（析构时 join）、实例借用（析构时归还）都是 RAII。

### 题 1：有界阻塞队列（生产者-消费者）

**要点**：
- 两个条件变量：生产者等"不满"，消费者等"不空"；
- 等待都带条件，防止虚假唤醒；
- `close()` 用 notify_all 叫醒所有人。

```cpp
#include <condition_variable>
#include <cstddef>
#include <mutex>
#include <queue>

template <typename T>
class BoundedQueue
{
public:
    explicit BoundedQueue(size_t cap) : cap_(cap == 0 ? 1 : cap) {}

    // 满了就等; 队列已关闭返回 false
    bool push(T v)
    {
        std::unique_lock<std::mutex> lk(m_);
        not_full_.wait(lk, [&] { return closed_ || q_.size() < cap_; });
        if (closed_)
            return false;
        q_.push(std::move(v));
        not_empty_.notify_one();
        return true;
    }

    // 空了就等; 队列已关闭且取空返回 false
    bool pop(T &out)
    {
        std::unique_lock<std::mutex> lk(m_);
        not_empty_.wait(lk, [&] { return closed_ || !q_.empty(); });
        if (q_.empty())
            return false;
        out = std::move(q_.front());
        q_.pop();
        not_full_.notify_one();
        return true;
    }

    void close()
    {
        {
            std::lock_guard<std::mutex> lk(m_);
            closed_ = true;
        }
        not_empty_.notify_all(); // 关闭是全局状态变化, 必须唤醒所有人
        not_full_.notify_all();
    }

private:
    const size_t cap_;
    bool closed_ = false;
    std::queue<T> q_;
    std::mutex m_;
    std::condition_variable not_empty_, not_full_;
};
```

### 题 2：线程池

**要点**：
- 任务队列 + 固定数量的线程；
- `packaged_task` 把返回值和异常都放进 `future`；
- 任务在锁外执行；
- 析构时把剩余任务做完再 join。

```cpp
#include <condition_variable>
#include <functional>
#include <future>
#include <memory>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <vector>

class ThreadPool
{
public:
    explicit ThreadPool(size_t n)
    {
        for (size_t i = 0; i < n; ++i)
            workers_.emplace_back([this] { loop(); });
    }

    ~ThreadPool()
    {
        {
            std::lock_guard<std::mutex> lk(m_);
            stop_ = true;
        }
        cv_.notify_all();
        for (auto &t : workers_)
            t.join(); // 析构中 join, 避免 std::terminate
    }

    template <typename F>
    auto submit(F f) -> std::future<decltype(f())>
    {
        using R = decltype(f());
        // packaged_task 不可拷贝, 而 std::function 要求可拷贝, 所以用 shared_ptr 包一层
        auto task = std::make_shared<std::packaged_task<R()>>(std::move(f));
        std::future<R> fut = task->get_future();
        {
            std::lock_guard<std::mutex> lk(m_);
            if (stop_)
                throw std::runtime_error("submit on stopped pool");
            tasks_.emplace([task] { (*task)(); });
        }
        cv_.notify_one();
        return fut;
    }

private:
    void loop()
    {
        for (;;)
        {
            std::function<void()> job;
            {
                std::unique_lock<std::mutex> lk(m_);
                cv_.wait(lk, [&] { return stop_ || !tasks_.empty(); });
                if (stop_ && tasks_.empty())
                    return; // 先把剩余任务做完再退出
                job = std::move(tasks_.front());
                tasks_.pop();
            }
            job(); // 在锁外执行任务; 任务抛出的异常被 packaged_task 存进 future
        }
    }

    std::vector<std::thread> workers_;
    std::queue<std::function<void()>> tasks_;
    std::mutex m_;
    std::condition_variable cv_;
    bool stop_ = false;
};
```

### 题 3：两个线程交替打印 1~n

**要点**：结束条件（`cur > n`）要写进等待条件里，否则最后一个数打印完，另一个线程会永远等下去。

```cpp
#include <condition_variable>
#include <mutex>
#include <thread>
#include <vector>

void alternatePrint(int n, std::vector<int> &out)
{
    std::mutex m;
    std::condition_variable cv;
    int cur = 1;
    auto worker = [&](int parity) { // parity: 1 打印奇数, 0 打印偶数
        for (;;)
        {
            std::unique_lock<std::mutex> lk(m);
            cv.wait(lk, [&] { return cur > n || cur % 2 == parity; });
            if (cur > n)
                return;
            out.push_back(cur++); // 面试时: printf("%d\n", cur++);
            cv.notify_all();      // 只有两个线程, notify_one 也可以; 但结束时必须能叫醒对方
        }
    };
    std::thread a(worker, 1), b(worker, 0);
    a.join();
    b.join();
}
```

### 题 4：IoU + NMS（和项目相关）

**要点**：先按分数排序，只删同类的框，复杂度 O(n²)。

```cpp
#include <algorithm>
#include <vector>

struct Box
{
    float x1, y1, x2, y2, score;
    int cls;
};

float iou(const Box &a, const Box &b)
{
    float iw = std::max(0.f, std::min(a.x2, b.x2) - std::max(a.x1, b.x1));
    float ih = std::max(0.f, std::min(a.y2, b.y2) - std::max(a.y1, b.y1));
    float inter = iw * ih;
    float uni = (a.x2 - a.x1) * (a.y2 - a.y1) + (b.x2 - b.x1) * (b.y2 - b.y1) - inter;
    return uni <= 0.f ? 0.f : inter / uni;
}

// 按类别的 NMS: 高分框只抑制与它 IoU > thresh 的"同类"低分框
std::vector<Box> nms(std::vector<Box> boxes, float thresh)
{
    std::sort(boxes.begin(), boxes.end(), [](const Box &a, const Box &b) { return a.score > b.score; });
    std::vector<bool> removed(boxes.size(), false);
    std::vector<Box> keep;
    for (size_t i = 0; i < boxes.size(); ++i)
    {
        if (removed[i])
            continue;
        keep.push_back(boxes[i]);
        for (size_t j = i + 1; j < boxes.size(); ++j)
        {
            if (!removed[j] && boxes[j].cls == boxes[i].cls && iou(boxes[i], boxes[j]) > thresh)
                removed[j] = true;
        }
    }
    return keep;
}
```

## 6. 踩坑故事

> 被问"遇到过什么难题"时用。按"背景 → 问题 → 怎么定位 → 怎么解决 → 结果"讲，**重点讲定位过程**。
> ✅ 是开发中真实发生的；🛡️ 是设计时考虑到并做过测试验证的，讲的时候如实说，不要说成自己踩过的坑。

**故事 1：NMS 下标混用 ✅**
- **背景**：把单路 demo 改成多路多模型时，重新检查后处理代码。
- **问题**：发现 NMS 排序后的下标和原始下标混用，而且没检查类别。我手工构造了例子验证：会出现车框把人框删掉、同类重复框删不干净。
- **解决**：统一用原始下标，并按类别判断。
- **顺带**：把全局标签数组改成每个模型自己持有，解决多线程初始化时的竞争。

**故事 2：头文件导致链接报"重复定义" ✅**
- **问题**：原来只有一个文件用线程池头文件，重构后多个文件都用，链接时报"重复定义"。
- **定位**：头文件里在类外定义了一个静态常量。在 C++14 里，每个包含这个头文件的源文件都会生成一份定义，违反了"单一定义规则"（ODR）；以前只有一个源文件包含它，所以没暴露。
- **解决**：改成枚举常量，枚举不需要单独定义。
- **收获**：理解了 C++17 为什么引入 `inline` 变量。

**故事 3：国标视频流"偶发解码错误" ✅**
- **问题**：用模拟平台接收国标视频流，解码时总报一次错，要判断是不是自己的封装有 bug。
- **定位**：分层排查。
  1. 先写脚本检查每个 PS 包结构，都正确；
  2. 再提取出裸 H.264 单独解码，仍然报错；
  3. 最后用二分法找出错的帧，发现只有最后一帧出错，而且它只收到一部分——是测试程序在 3 秒时停止接收，把最后一帧截断了。
- **结论**：封装没问题，是测试方法的问题。
- **收获**：用证据说话，测试方法本身也可能出错。

**故事 4：推流服务器重启导致进程直接退出 🛡️**
- **背景**：往已断开的连接写数据会触发 SIGPIPE，默认直接杀死进程，而且没有日志。
- **设计**：忽略 SIGPIPE，写失败时关闭旧连接、等待后重连，重连后第一帧强制关键帧。
- **验证**：用 mediamtx 做服务器，推流中途把它关掉再重启。日志显示断开、重连、恢复推流，进程没有退出。

## 7. 项目不足与改进

> 面试官常问"有什么不足"。挑 2~3 条，按"现状 → 影响 → 怎么改"来说，能主动说出缺点是加分项。

| 不足 | 怎么改 |
|---|---|
| 每路 3 个线程，路数多了线程太多 | 改成少量工作线程 + 事件驱动 |
| 每帧都新分配图像内存（1080p 约 6MB） | 做图像缓冲池复用 |
| NPU 输入还有一次内存拷贝 | 让 RGA 直接写进 NPU 的输入内存（零拷贝） |
| 跳帧时框会滞后 | 中间帧用跟踪算法预测框的位置 |

| 没有自动化单元测试 | 给融合、封装、配置解析这些纯逻辑模块写单元测试 |

## 8. 上板要测的数据

面试一定会问"跑多少帧、延迟多少"。上板后至少测这些：

| 数据 | 怎么拿 |
|---|---|
| 每路帧率、推理耗时 | 程序日志里的性能报告（`chN.out`、`chN.infer`） |
| NPU 三个核占用 | `sudo cat /sys/kernel/debug/rknpu/load` |
| 整机和各线程 CPU | `top -H -p 进程号` |
| 端到端延迟 | 拍计时器（见 F2） |
| 内存是否稳定 | 跑几个小时，看 `/proc/进程号/status` 里的 VmRSS 是否平稳 |
| 故障恢复 | 拔一路网线、重启推流服务器，看能否自动恢复 |

同时看启动日志，确认硬件真的用上了：
- 解码器显示 `mpp`；
- 编码器显示 `mpp h264 encoder`；
- 没有 `rga ... fallback` 的警告。

**面试时这样说数字**："在 RK3588、4 路 1080p、yolov5s 的条件下，每路 xx fps，NPU 占用约 xx%，延迟约 xx 毫秒，连续运行 xx 小时内存平稳。"

条件、数字、稳定性，三样都要有。
